# 모달 탐색 병목 개선 — 수정된 단계별 계획

## 1단계 — 완료

정책 파일 분리, 초기화 버튼 및 첨부 영역 미리보기 제외. 대표 공고에서 약 118초에서 61초로 감소했다. 기존 상세 내용은 보존했고 안내 캡처가 추가되었다. 전체 반복 검증은 별도로 수행한다.

## 2단계 — 이번 구현 범위

- 조건 입력이나 업체 선택을 하지 않는 현재 수집에서는 확인된 업체 검색 동작을 제외한다.
- 현장설명회참여업체조회 모달(PBAB007_01)의 사업자등록번호 검색 창 열기 및 조건 검색 실행 버튼을 제외한다.
- 해당 모달의 조달업체 선택 창(EtpsPL) 안에서는 조건 검색 실행 및 결과 건수 적용 버튼을 제외한다. 상위 검색 창 열기를 제외하면 보통 도달하지 않지만 직접 탐색되는 경우에도 같은 정책을 적용한다.
- 소유 모달 ID, 정확한 버튼 ID, 버튼형 요소 여부, 문구를 조합해 판정한다. 패턴과 문구는 modal-policy.ts에서 관리한다.
- 다른 화면의 검색 및 공고·사전규격·발주계획 상세 링크는 유지한다. 현장설명회참여업체조회 모달 자체도 유지한다.
- 기존 안내 모달 안정화 개선 계획은 보류한다. 최대 관찰 8초, 안정화 1.5초, 확인 간격 125ms를 바꾸지 않는다. isNoticeDialog 함수는 수집 흐름에 추가 연결하지 않는다.
- 입력 검증 안내와 빈 업체 검색 화면의 캡처 감소는 의도된 변화다. 기존 공고 상세 내용·표·첨부·관련 키는 보존해야 한다.
- 정책 및 Chrome 회귀 테스트, 타입 검사 후 대표 공고 1건을 실제 측정한다. 시간과 수집 내용 비교를 보고하고 다음 단계 요청을 기다린다.

## 3단계 — 별도 요청 후 진행

기존 manifest 공고 3건을 같은 순서로 3회 측정하고 수정 전 기록과 비교한다. 필요한 공고 내용 보존 및 시간 감소를 확인한다. 남은 안내가 실제 지연을 만든다는 근거가 생기면 별도 수정안을 제시한다.

## 규칙 추가 원칙

실측에서 확인된 불필요한 동작만 좁은 조건으로 추가하고, 정상 조회가 제외되지 않는 테스트를 함께 작성한다. 문구만으로 모든 검색이나 모든 안내 모달을 일괄 제외하지 않는다. DB·PDF·관련 공고 확장·상시 관측 화면·오류 진단 시스템은 이번 범위가 아니다.
